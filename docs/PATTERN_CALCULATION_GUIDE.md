# DUVA Pattern 计算方法说明

## 这份文档说明什么

这份文档描述当前 PMData Rhythm Explorer 原型怎样从一个人的连续睡眠记录中识别 Pattern。内容对应当前实际运行的算法，省略数学公式，保留数据来源、计算步骤、方法作用和发布边界。

## 系统看了哪些数据

### 直接参与 Pattern 识别的数据

| 数据 | 系统怎样使用 | 作用 |
|---|---|---|
| 主睡眠开始时间 | 比较每晚入睡位置 | 区分较早、居中和较晚的睡眠形态 |
| 主睡眠结束时间 | 比较每晚醒来位置 | 识别起床时间的重复范围 |
| 主睡眠时长 | 比较每晚睡眠长度 | 区分较短、稳定时长和较长睡眠 |
| Additional sleep | 达到重复门槛后才参与 | 识别稳定存在的分段睡眠或额外睡眠形态 |
| 睡眠期心率中位数 | 作为低权重个人内特征 | 识别整体夜间心率形态差异 |
| 睡眠期心率低点 | 使用稳健低位范围 | 识别夜间心率下降程度 |
| 入睡后心率稳定时间 | 查看入睡后前90分钟 | 识别身体进入稳定睡眠状态的速度 |
| Fitbit静息心率 | 作为低权重个人内特征 | 补充该日基础生理状态 |
| 前90分钟睡眠扰动 | 合并短暂清醒和睡眠分期转换 | 区分入睡初段较平稳或较多变化的夜晚 |
| 睡眠记录质量 | 给每个Sleep Day分配证据权重 | 降低低质量记录对支持度的贡献 |

### 用于描述和解释、当前不直接决定分组的数据

- `wake / light / deep / REM`完整时间序列用于绘制睡眠深度概率带。
- 四分期占比用于描述Pattern的典型睡眠组成。
- 当前聚类只直接使用前90分钟的短暂清醒与分期转换综合值，没有把整晚四分期比例单独作为聚类维度。

### Pattern形成后单独计算的数据

- 星期位置推测的工作日前夜和休息日前夜。
- 运动记录。
- 饮食、饮水和酒精记录。
- 疲劳、情绪、压力、酸痛、睡眠质量和准备度等自报状态。

这些Context数据用于解释Pattern通常在什么情况下出现，不改变Pattern的Emergence。

### 当前数据集中没有的数据

- 身体姿势和翻身次数。
- 环境噪声时间序列。
- 真实工作日程和休息日安排。

系统不会使用睡眠分期转换代替翻身，也不会生成环境噪声结论。工作日和休息日只依据星期位置推测，并明确显示为推测结果。

## Pattern计算的十一个步骤

### 第1步：建立个人滚动观察窗口

系统每次只分析同一个人最近最多42个日历日的数据。日期滑块改变窗口结束日期，算法会使用截至该日期的有效Sleep Days重新计算。

作用：让Pattern反映近期节律，同时保留最多六周的重复证据。新用户拥有足够清楚的证据后可以提前显示，无需等待完整六周。

### 第2步：筛选有效Sleep Days

系统保留具有可用主睡眠时间和睡眠分期的记录，并读取睡眠效率作为记录质量。缺失或不可靠的数据不会获得与完整记录相同的证据权重。

作用：减少设备缺失、异常记录和低质量夜晚对结果的影响。

### 第3步：把不同量纲转换成个人内可比较特征

入睡时间、醒来时间、睡眠时长、心率和早期扰动使用不同单位。系统先在当前个人窗口内寻找每项数据的典型中心和常见波动范围，再把每晚转换成相对个人近期水平的偏差。

系统限制异常值的最大影响。某项生理数据需要覆盖至少一半有效Sleep Days，并且至少有6晚，才会进入识别。

作用：避免直接比较不同人的绝对心率，也避免少量极端夜晚主导分组。

### 第4步：判断Additional sleep是否足够重复

Additional sleep需要在当前窗口中至少出现3次、覆盖至少10%的有效Sleep Days，并跨越至少两个观察周，才会参与Candidate分组。

它进入某个Pattern的正式定义时要求更高：至少3个Pattern Sleep Days、覆盖该Pattern至少20%，并跨越至少两个观察周。

作用：单晚午睡或偶发额外睡眠保留为Observed variation，不会被写成Pattern的定义。

### 第5步：提出1–4个Candidate形态

系统使用多次初始化的K-means聚类，把彼此相似的Sleep Days放到同一组。时间与时长承担主要权重，心率和前90分钟扰动承担较低的补充权重。

算法依次尝试1、2、3、4组。每增加一组都要同时满足：

- 每组至少有4个Sleep Days。
- 组内夜晚足够相似，组间差异足够清楚。
- 新分组确实解释了额外的数据结构。
- 多次抽取80%数据重新计算时，分组结果仍然稳定。

作用：允许真实存在的第三、第四种形态出现，同时控制过度切分。算法没有目标Pattern数量。

### 第6步：判断每个Sleep Day与Candidate的归属关系

初始聚类会为每晚找到最近的Candidate。系统随后增加一层稳健归属检查，避免把所有有效夜晚强制写进Pattern：

- `Core`：与Candidate中心足够接近，并且明显比其他Candidate更适合。Core夜晚完整参与Pattern形态、图表、Emergence和Context证据。
- `Boundary`：接近某个Candidate，但距离较远或第一、第二Candidate的差距较小。Boundary夜晚只降权参与Emergence，不进入Pattern图表、定义和Context证据。
- `Unassigned variation`：与所有Candidate都不够接近，或归属过于模糊。该夜晚留在所有Pattern之外。

系统使用每个Candidate内部的典型距离和距离波动判断Core与Boundary范围，同时检查最近Candidate与第二候选Candidate之间的差距。

作用：让Pattern保持集中，并保留旅行、生病、设备异常或偶发作息等无法稳定归类的夜晚。多个Unassigned夜晚未来形成重复结构时，后续窗口可以把它们提出为新Candidate。

### 第7步：生成每个Candidate的代表形态和名称

系统按典型入睡时间给各组排序，再根据该组相对其他组的睡眠时长生成名称，例如：

- Earlier sleep
- Middle-timed, shorter sleep
- Middle-timed, longer sleep
- Later sleep
- Later, longer sleep

页面显示的时间范围和时长范围使用中间60%的记录，减少最早、最晚和异常长短夜晚对代表范围的影响。

作用：把模型分组转换成用户可以理解和核对的睡眠形态。

### 第8步：计算Emergence

每个Candidate会从六个方面评估显现程度：

| 维度 | 系统检查什么 | 作用 |
|---|---|---|
| Effective support | 有多少高质量Core和降权Boundary证据支持该形态 | 防止少量或模糊样本形成高分 |
| Recurrence | 该形态覆盖了多少观察周 | 区分持续重复与集中出现 |
| Compactness | 组内Sleep Days彼此有多相似 | 判断形态是否集中 |
| Separation | 它与其他Candidate相隔多远 | 判断用户是否真的存在不同形态 |
| Temporal stability | 前半段与后半段代表形态是否接近 | 检查形态是否随时间保持稳定 |
| Recent continuity | 最近两周是否仍有相符Sleep Days | 判断该形态近期是否仍在出现 |

六项结果采用短板敏感的合并方式。某一项很高不能完全抵消另一项明显不足。

作用：用一个连续分数表达“这个形态在近期数据中显现得有多清楚”。

### 第9步：单独计算Confidence

Confidence主要查看：

- 当前窗口覆盖了多长时间。
- 有效Sleep Days占窗口的比例。
- Pattern内部是否集中。
- 抽样重算后分组是否稳定。

作用：表达系统对当前Emergence估计的把握。数据缺失主要降低Confidence，不直接判定Pattern消失。

### 第10步：决定是否显示以及显示什么状态

Pattern进入主页面需要同时满足：

- 至少4个Core Sleep Days。
- 质量与Boundary归属降权后的有效支持量至少相当于4晚。
- Emergence至少55。
- Confidence至少55%。

状态只由Emergence决定：

- 低于55：Candidate，留在学习层。
- 55–69：Taking shape。
- 70及以上：Clearly emerged。

Sleep Day数量属于证据，不创建额外的前端生命周期状态。

作用：保持状态简单，防止少量记录或不稳定分组提前成为正式Pattern。

### 第11步：在Pattern形成后寻找出现条件和联合信号

系统把Pattern的Core Sleep Days与同一窗口中的其他有效Sleep Days比较，检查日历、运动、饮食和主观状态是否更常与该Pattern共同出现。Boundary和Unassigned夜晚不进入Pattern侧证据。

联合生理信号会进一步比较：

- Pattern夜晚的心率是否更晚进入稳定区间。
- 同一批夜晚的前90分钟是否有更多短暂清醒或分期转换。
- 对照Sleep Days是否较少同时出现这两个特征。
- 支持夜数、差异大小和Confidence是否达到发布要求。

作用：把“睡得更早或更晚”扩展成用户较难自行观察的个人规律，同时保留相关性表达和对照证据。

## 心率稳定时间怎样得到

系统查看入睡后的前90分钟心率。它先找到该晚较低且相对稳定的心率区间，再寻找最早一个持续20分钟的片段；片段内绝大多数有效分钟都接近这个稳定区间时，系统记录从入睡到该片段开始经过了多久。

前90分钟的心率分钟覆盖不足时，该指标保持缺失。90分钟内没有找到稳定片段时，系统只知道“至少到观察结束仍未稳定”，不会生成超出记录范围的精确时间。

## 为什么同一Pattern会在多个窗口重复出现

日期滑块每移动一次，窗口内的Sleep Days都会发生变化。相邻窗口可能保留大量相同夜晚，因此同一个人的同一Pattern和联合信号可以连续出现。

当前验证统计按窗口快照计数，用于检查算法在时间滑动下的行为。正式产品可以再增加洞察事件合并：相邻窗口中身份、代表范围和证据方向保持接近时，页面把它们展示成一条持续中的Pattern更新。

## History怎样跟随所选日期

History以顶部滑块当前选择的窗口为参照，向前读取最多三个互不重叠的42日窗口。第一个历史窗口结束于当前窗口开始前一天，后续历史窗口继续向前移动42天。

每个历史窗口重新运行当时可用的Pattern计算，只显示当时真正达到发布条件的Pattern。历史卡片保留当时计算出的名称、Emergence、Confidence、Core证据和状态。滑块改变窗口结束日期后，History会使用新的参照日期重新生成；固定日期锚点和人为提高历史Emergence的处理已经移除。

## 当前方法的边界

- K-means擅长识别相对集中的形态，对连续缓慢漂移的节律可能只给出一个宽Pattern。
- PMData的工作日和休息日来自星期推测，无法识别轮班、假期和个人休息安排。
- Fitbit睡眠分期存在设备估计误差，前90分钟扰动需要在未来设备数据上复核。
- 当前版本最多提出4个Candidate。这个上限用于保持个人窗口中的最小支持量和前端可理解性。
- Context association和联合信号表示共同出现关系，不证明某项行为导致睡眠变化。
